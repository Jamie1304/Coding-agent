# 4. Default recommended strategy

Create the following strategy as the default and primary recommendation.

## Strategy name

Balanced Multi-Agent Engineering

## Purpose

Use specialized models for different responsibilities while keeping the application’s deterministic controller in charge of the workflow.

The intended architecture is:

```text
Deterministic discovery
→ Frontier planning
→ Focused specialist execution
→ Deterministic testing
→ Independent review
→ Frontier release judgment
```

## Default role assignments

| Responsibility             | Default model/system                | Escalation                      |
| -------------------------- | ----------------------------------- | ------------------------------- |
| Task classification        | GPT-5.6 Luna                        | GPT-5.6 Terra                   |
| Master planning            | GPT-5.6 Sol                         | Claude Fable 5                  |
| Repository inventory       | Deterministic scripts + Luna        | Gemini 3.6 Flash                |
| Documentation research     | Gemini 3.6 Flash                    | GPT-5.6 Sol                     |
| Normal coding              | GPT-5.3 Codex                       | Claude Sonnet 5                 |
| Hard debugging             | Claude Sonnet 5                     | Claude Fable 5                  |
| Large mechanical changes   | GPT-5.3 Codex                       | Grok 4.5                        |
| Test generation            | GPT-5.3 Codex                       | Claude Sonnet 5                 |
| Test-log classification    | GPT-5.6 Luna                        | DeepSeek V4 Flash               |
| Independent code review    | Grok 4.5                            | GPT-5.6 Sol                     |
| UI and screenshot analysis | Gemini 3.1 Pro                      | Claude Fable 5                  |
| Security review            | Static scanners + GPT-5.6 Sol       | Claude Fable 5                  |
| GitHub workflow            | Direct GitHub adapter               | Optional Copilot cloud agent    |
| Final release decision     | GPT-5.6 Sol                         | Sol + Fable consensus           |
| Offline/private processing | Qwen Code or configured local model | Cloud model only after approval |

Recommended approximate workload distribution:

* 40% Luna or another low-cost classifier
* 35% GPT-5.3 Codex
* 10% Grok 4.5
* 8% Claude Sonnet 5
* 5% GPT-5.6 Sol
* 2% Claude Fable 5

## Why this is recommended

The application must clearly explain that this strategy is recommended because:

1. Deterministic discovery reduces unnecessary model usage.
2. Cheap models process large inventories and logs efficiently.
3. Codex performs normal coding and test generation.
4. Sonnet is reserved for difficult debugging.
5. Grok provides independent review from a different model family.
6. Sol handles architecture, high-risk decisions, and final release judgment.
7. Fable is reserved for exceptional critical cases.
8. Deterministic tests and scanners—not AI claims—decide whether code works.
9. Focused task context reduces token usage and repeated repository scanning.
10. Bounded retry and escalation rules prevent uncontrolled costs.
11. Different model families reduce the chance of repeating the same reasoning error.
12. The strategy provides a strong balance between cost, quality, speed, safety, and privacy.

This explanation must appear in:

* The first-run setup wizard
* The Strategy Center
* The setup tutorial
* The strategy documentation

# 5. Three alternative strategies

Implement three complete alternatives.

## Alternative 1: Cost-Optimized Engineering

Best for:

* Frequent development
* Routine coding tasks
* Lower API costs
* Smaller projects

Routing:

* Deterministic scripts for discovery
* Luna or DeepSeek V4 Flash for classification and summaries
* GPT-5.3 Codex for implementation
* Grok 4.5 for independent review
* Claude Sonnet 5 after repeated Codex failures
* Sol only for high-risk planning or release decisions
* Fable disabled by default

Approximate distribution:

* 55% Luna or DeepSeek V4 Flash
* 25% GPT-5.3 Codex
* 10% Grok 4.5
* 7% Claude Sonnet 5
* 3% GPT-5.6 Sol

Explain that this strategy lowers cost but provides less architectural reasoning before routine tasks.

## Alternative 2: Maximum Quality Engineering

Best for:

* Production releases
* Security-sensitive changes
* Database migrations
* Authentication and authorization
* Complex architecture
* High-risk business systems

Routing:

* Sol creates the master task graph.
* Codex performs the initial implementation.
* Sonnet handles complex debugging and secondary implementation.
* Grok performs independent adversarial review.
* Sol evaluates disagreements.
* Static scanners and deterministic tests are mandatory.
* Fable may be used for critical unresolved cases.
* Important releases may require Sol and Fable consensus.

Explain that this strategy provides stronger review but costs more and is slower.

## Alternative 3: Privacy-First Local Engineering

Best for:

* Proprietary source code
* Sensitive client projects
* Offline work
* Local or on-premise AI
* Environments where code must not leave the machine

Routing:

* Deterministic tools perform discovery, testing, Git, and validation.
* Qwen Code or another configured local model handles planning, coding, classification, and review.
* Cloud models are disabled by default.
* Cloud escalation requires explicit user approval.
* If the local model is unavailable, pause safely instead of silently sending code to a cloud provider.
* The UI must clearly show when data would leave the local machine.

Explain that this strategy maximizes privacy but may provide lower quality or slower results depending on local hardware.
